# 第一版物理架构

## 结论

树木物理不需要继续实现完整 Sable。样例项目对 Sable 的核心依赖是
SubLevel 装配体、刚体状态、质量属性、世界碰撞、刚体碰撞、速度/冲量和碰撞回调。
Spring、Rope、Bearing、Magnet 等系统不在树木倒伏的关键路径上。

当前第一版的能力对应如下：

| 树木物理需求 | 第一版状态 |
| --- | --- |
| 多方块共享一个刚体 | 已实现，`PhysicsAssembly` 只创建一个 Cannon Body |
| 复合碰撞几何 | 已实现，精确覆盖占据体素并贪心合并相邻方块 |
| 原木/树叶质量和质心 | 已实现，逐块加权计算质心 |
| 装配体和世界方块碰撞 | 已实现，沿用 Cannon-es-2 的原版方块碰撞解析与动态扫描 |
| 装配体相互碰撞 | 已实现，Cannon compound 直接参与窄相和求解 |
| 线速度、角速度、力和冲量 | 已实现 |
| 碰撞回调 | 已实现，包含碰撞点、法线和冲击速度 |
| 碰撞点定位到装配体方块 | 已实现，`getBlockAtWorldPoint()` |
| 多方块同步平移和旋转 | 已实现，每个视觉实体跟随同一刚体姿态 |
| 睡眠与生命周期基础 | 已实现，首次休眠后累计各段休眠时间，运动期间暂停但不清零 |
| 自然树根标记 | 已实现，25 个直立树和 5 个倒木地物统一生成 `natural_tree_root` |

| 树扫描和砍伐触发 | 已实现，破坏前洪泛验证、多根标记原木归属、六向派生叶距梯度和脱离组件 |
| Sable 世界方块表面参数 | 已实现，冰/泥巴/蜂蜜等摩擦与黏液恢复系数由数据生成 |
| 简单浮体物理 | 已实现，逐块采样浸没比例、浮力和采样点速度阻力 |
| 易碎世界方块 | 已实现，碰撞速度达到阈值后延迟破坏并生成原版掉落 |
| 装配体易碎块 | 已实现，树叶与植物附着物使用阈值 0 的无响应传感器；蜂巢/可可豆使用阈值 4；破碎时同步清理断连叶片和附着物 |
| 结构化原木破碎 | 已实现；巨型丛林树分支优先并逐侧侵蚀 `2x2` 主干，巨型云杉在六层保护底座以上横向折断，华丽橡树仅破碎单格主干外分支；断连结构与失去支撑的叶片和附件一次性转为掉落物 |
| 世界树叶与植被 | 自然非持久树叶为易碎接触传感器，人工/持久树叶保持实体碰撞；草花等保持无碰撞且不会被树破坏 |
| 休眠后唤醒 | 常规事件即时唤醒，并以低频物理环境签名兜底无事件的生存玩法方块变化 |
| 实体伤害 | 已实现，动态原木点速度驱动伤害、击退与 4 tick 冷却 |
| 整树最终掉落 | 已实现，先持久化终止事务，再单批生成；最多 64 个剩余方块保持各自世界位置，超过时在最终包围盒下方集中并按原版堆叠上限合并 |
| 重载存储恢复 | 已实现，保存姿态、速度、剩余方块、休眠累计值、衰减与工具状态 |
| 跨玩家加载域处理 | 已实现，当前范围可读而预测/外向护栏不可读时连续确认后直接掉落 |
| 装配体碰撞盒 Debug | 已实现，debug 构建绘制约 `1/16` 格粗的真实 compound 边线 |
| 玩家施力 | 已实现，左键精确命中点冲量；手持任意物品右键长按以有限幅弹簧阻尼力牵引 |
| 生命周期热路径收敛 | 已实现，合并实体查询、复用探针缓冲与错峰活动树快照 |

| 世界扫描热路径收敛 | 已实现，自适应选择 body AABB/shape 数值并集，以原生非空气批量筛选减少宿主调用，世界布局未变时复用 Cannon 静态体 |
| Spring/Rope/Constraint 全套 API | 明确不实现，当前目标不需要 |

## 源码边界

- `src/physics.ts`：最小公开物理 API、装配体和基岩视觉绑定。
- `src/physics/`：Cannon 内核、体素合并、碰撞形状解析、视觉 renderer 与 Debug 适配。
- `src/tree/`：树块表示、fragment 布局、叶片质量和染色。
- `src/gameplay/`：树木选择、交互、外力、生命周期、世界事务和结算规则。
- `src/data/`：运行时数据访问；`src/data/generated/` 只存放生成结果。
- `src/persistence/`：分段 JSON 与双代际原子切换存储。
- `src/main.ts`：玩家事件、世界方块事务移除、砍伐初速度和玩法生命周期接线。

完整目录职责与生成规则见 `docs/development/project-structure.md`。

`physics.js` 较大的主要原因是 Cannon runtime 和原版/Sable 对照碰撞数据。这些属于
世界方块碰撞正确性的一部分，不是旧 demo 或完整 Sable API 残留。

## 已知边界

- 单装配体最多 6144 个视觉方块，局部坐标范围为 `[-511, 511]`。
- 叶片选择以六向邻接重建原项目的叶距，以 26 邻域沿距离递增方向传播；距离场
  只裁剪叶片，不参与原木归属。距离场超过 16384 个叶片时回退到原有六层洪泛，
  不会因此拒绝整棵树。
- 方块按固定槽 fragment 合并为少量显示实体；高方块数时，客户端 fragment 几何和属性解码
  仍可能先于 Cannon 求解成为瓶颈。
- 质量按块加权，但 convex/compound 惯性仍采用 Cannon 的 AABB 近似，这是
  Cannon-es-2 已声明并通过肉眼验收的差异。
- 当前碰撞信号是每次 Cannon `collide` 接触，不是去重后的 begin/end 状态机。
- 玩家牵引沿用 Simulated 把手的每轴最大 120 线性力、240 刚度、30 阻尼和
  4.5 角阻尼；目标距离限制为 2 至 2.5 格，连续力会在每个 Cannon 子步重新计算，
  不会因一游戏 tick 内的三个物理子步而只剩三分之一效果。左键冲量使用按落地
  单原木标定的后端系数，补偿 Cannon 首次地面接触相对 Sable/Rapier 更大的损失。
- 浮体模型只采样每个装配体方块中心，不计算精确水线截面、流体流向或造波。
- 装配体树叶保留 compound 几何但关闭 Cannon 求解响应；实体和传感器体素分别
  贪心合并。藤蔓、胎生苗、垂根和苍白垂苔使用相同阈值 0 传感器；蜂巢和可可豆
  使用 Sable 的速度阈值 4。每次破碎前以剩余原木和叶片做 26 邻域支撑传播，断连
  叶片与附着物并入同一删除批次，因此只重建一次 collider。世界非持久自然树叶采用原项目
  `LeavesBlockCallback` 的 `0` 速度阈值和相同传感器语义；persistent 叶片或命中
  人工记录的叶片保持实体碰撞且不会被物理回调破坏。
- 原木破碎独立于树叶质量档和活动预算，只在创建时识别连续 `2x2` 丛林/云杉主干或带有真实
  径向分支的连续单格华丽橡树主干。普通直立树与普通云杉不创建破碎计划。巨型丛林树把主干外
  原木预分为最多四个分支批次，并在受保护锚点
  核心以上预生成最多四个主干裂口带。活动期间只复用既有 Cannon 碰撞回调，同一 tick
  聚合一个最强冲击，不增加世界读取、实体查询或原木探针。分支清空后，受约束随机算法
  最多同时扩展两个裂口；每次删除后从真实渲染锚点执行一次 26 邻域传播，失联原木、树叶
  和附件合并为一次装配体删除、一次 collider 重建和一批原版 LootTable 掉落。巨型云杉在
  六层保护底座以上生成最多四个横断带，优先处理最靠近碰撞点的断面并在下一次有效冲击补完；
  华丽橡树只生成最多四个径向分支批次，整条单格主干均为保护核心。每根原木 sleep 成本在砍伐时
  保存一次，每次成功断裂只按实际删除原木数做常数时间扣减。完整协议见
  `docs/design/tree-log-breakage.md`。
- 装配体树叶和植物附着物共享每棵活动树每 tick 最多 64 个易碎块补充探测，弥补
  合并传感器只产生一次 begin-contact 的情况；断连传播只在已有破碎批次发生，
  没有常驻逐 tick 扫描。落叶堆、草花和树苗沿用原版无碰撞
  形状，且不进入 Sable/Tree Physics 易碎名单。
- 藤蔓、垂根、苍白垂苔和悬挂胎生苗只有在实际可避免的附件 fragment/controller 达到当前质量档
  阈值时才在砍伐阶段破坏并分批掉落；普通数量仍保留完整装配体行为。蜂巢、可可豆、嘎吱之心、
  红树根和泥泞红树根不参与裁剪。完整阈值与恢复协议见
  `docs/performance/attachment-load-shedding-2026-07-26.md`。
- 巨型活动树的 collider 扫描优先用 `Dimension.getBlocks()` 批量筛选非空气候选，再对候选执行原有
  液体、sensor、材质和碰撞形状解析；任一异常会在同 tick 完整回退逐坐标读取。默认 colormap 的
  统一色藤蔓使用单一 overlay，渐变藤蔓仍保留逐槽精确取色。实机依据、诊断字段和验收门槛见
  `docs/performance/giant-tree-runtime-optimization-2026-07-26.md`。
- 原世界蜂巢进入装配体时直接置为空气，不在转移阶段生成蜜蜂。装配体蜂巢真正破碎或
  最终结算为掉落物时，根据快照中的 `honey_level` 粗略生成蜜蜂：0 级不生成，1-2 级
  生成 1 只，3-4 级生成 2 只，5 级生成 3 只；这是对无法序列化实际入住蜜蜂数据的
  近似处理。已经提前破碎的蜂巢不再存在于最终结算列表，因此不会重复生成。
- 原木计时依据 [Minecraft Wiki Breaking](https://minecraft.wiki/w/Breaking#Calculation)
  的硬度 2、工具速度和效率附魔公式。急迫、挖掘疲劳、水下与悬空等临时玩家
  状态不写入树木寿命。
- 伤害仅在实体头部落入动态原木体素时触发；物品实体和物理显示实体在查询后
  立即排除，不会被伤害或随装配体清理。
- Debug 模式每条碰撞边使用 9 条线形成 `0.0625` 格横截面，仅用于肉眼测试。
- 同机 Node 成对验收中，当前 primitive 场景 10 体约 `1.64ms`、32 体约
  `5.03ms`，相对本轮优化前的 `1.66ms`、`5.02ms` 无退化。完整碰撞树冠由
  每棵 17 shape 降为 14 shape；单棵活动树由约 `0.60ms` 降至 `0.50ms`，10 棵、
  1230 方块由约 `5.53ms` 降至 `5.44ms`。10 棵休眠树约 `0.22ms`，均低于
  原定 10 体 `50ms` 预算。Node mock 低估了基岩宿主 `getBlock()` 和实体写入成本，
  数据只用于同机回退比较。
- 原木 `pillar_axis` 已映射到视觉局部旋转；其他任意方块状态仍不会完整投射到物品模型。
- 活动树快照按 `1/20` 分片逐 tick 刷新，休眠树在每 20 tick 落盘前全部刷新，
  因而累计休眠 tick 不会因错峰丢失；写入先完成新代际全部分段，再切换清单，
  中途失败仍读取旧代际。恢复只发生在同维度玩家水平/垂直 96 格内且区块可读时。
- 重载期间休眠计时暂停，只恢复已累计的 sleep tick，不按现实离线时间推进。
- 跨域探测使用当前 AABB、`0.35s` 扫掠范围和远离玩家方向的一区块护栏；正常
  玩家加载域变化连续 2 tick 成立才结算。世界突然关闭而没有最后一个可执行 tick
  时保留存档，下一次加载后恢复，而不会冒险在不可读区块生成掉落。
- 基岩版没有 Java 版可直接读取的树叶距离状态；当前以各原木分量和周边外来原木
  为多源、最多 6 格洪泛，距离相同或外来树更近的叶片保守留在世界中。
- 活动装配体附近每个物理步仍读取当前世界；世界坐标不做跨步缓存。collider 扫描先用原生
  `getBlocks()` 筛出非空气候选，再对候选调用 `getBlock()`；API 异常时完整回退逐坐标读取。
  两个及以上 shape 会按真实并集体积与管理成本自适应选择密集 AABB 或带角速度扫掠的 shape AABB
  数值行区间并集。扫描后的碰撞盒按数值字段比较，布局未变化时保留现有 Cannon 静态体；方块
  碰撞形状仍按当前状态和邻居实时解析。
