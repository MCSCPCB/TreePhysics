# 阶段 2：Fragment 装配体放置箱子

阶段 2 只处理 fragment 渲染链路的物理装配体，不处理一方块一实体链路和混合装配体。

需要实现的功能：
-这里说的功能都是通用的，只不过我们在本阶段只纳入箱子到白名单，以后通过修改白名单就可以纳入更多其他方块

- 玩家潜行时，可以向装配体相邻的空局部方块位置放置关闭的原版箱子。
- 只支持 `minecraft:chest`，保留箱子的东、南、西、北四向状态。
- 箱子正面根据玩家视线方向确定，并随装配体整体旋转、翻转。箱子共享装配体的局部上下方向。装配体翻转后，箱子在世界空间中也随之翻转，不产生朝上或朝下的非法箱子状态
- 箱子使用新fragment实体系列 `cube_block_fragment_XXXX` 显示，并与现有树木 fragment 共存于同一装配体。
- 放置后装配体的质量、质心、惯性、碰撞、浮力、视觉和持久化数据正确更新。
- 原有方块的世界位置和运动状态保持连续，装配体被正确唤醒。
- 箱子加入后，装配体暂停自动结算和树叶衰败；树叶、附件的冲击破碎继续有效。
- 放置失败时不消耗箱子，也不留下部分更新。
- 箱子复用现有装配体方块挖掘链路；破坏后正确更新物理、视觉、拓扑和持久化，并产生原版式裂纹、粒子、音效、掉落与工具耐久消耗。
- 箱子的类型、局部坐标和方向状态等所有可以访问的方块数据都要随装配体保存、恢复。
- 新增箱子的视觉不能暴露初始姿态修正过程，要和现在的链路一样。
- 预留显式装配体结算入口，但本阶段不绑定新的玩家操作。

本阶段不实现箱子容器功能、双箱连接、复杂方块状态、未知方块适配、一方块一实体放置或混合渲染。
