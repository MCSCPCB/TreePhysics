# 树木结构化原木破碎

## 目标

巨型丛林树受到真实碰撞后先损失分支，再在主干上形成少量随机裂口。裂口逐侧侵蚀仍在承重的
`2x2` 主干；最后一条连接断开时，与渲染锚点失去 26 邻域原木连接的整个远端结构转为原版掉落。
整个过程始终只有一个物理装配体，不创建子刚体、子装配体或额外显示实体。

华丽橡树复用同一事务和冲击模型，但只允许单格主干外的径向分支破碎；从砍伐锚点延伸的完整
竖直主干永久保护，不生成任何主干裂口。

低性能档在创建刚体前复用上述资格判定和分支分组。符合条件的巨型丛林树及华丽橡树不会把
分支原木加入装配体；分支和因此失去主干支撑的树叶、附件直接进入持久化分片掉落事务。主干的
质量、惯量、浮力、破碎时间和碰撞表示均只按保留结构计算。该路径不适用于巨型云杉，也不改变
高性能档的装配与运行时断裂行为。

巨型云杉使用独立的横向折断策略。它不把规整 `2x2` 主干纵向削成细柱，而是在碰撞位置附近的
预设横断带上分两侧形成自然裂口。第二侧断开后，上方失联树干和树冠整体转为掉落物；底部至少
六层完整 `2x2` 主干永久保留。普通单格云杉不启用该机制。

## 资格判定

资格只在装配体注册时利用已经捕获的原木快照计算一次：

1. 所有捕获原木都属于 `jungle` family。
2. 砍伐原点水平位置落在同一个 `2x2` 主干底面内。
3. 该底面至少存在连续四层完整原木。砍伐层允许因触发方块已被移除而只剩三根；验证从其上方
   的完整层开始。

华丽橡树资格同样只计算一次：全部原木属于 `oak` family；真实渲染锚点所在列至少有连续四根
剩余原木；列外至少有两根分支原木且水平伸展达到两格。锚点列全部原木为保护核心。分支从与
主干相邻的根部按东西南北径向传播并合并为最多四批；短侧结普通橡树不会命中。

巨型云杉资格只计算一次：全部原木属于 `spruce` family；砍伐原点落在连续完整的 `2x2` 主干
底面内；保护六层完整主干后仍有足够高度生成横断带。原版巨型云杉和巨型松树满足该结构条件，
普通云杉及过矮的玩家结构不满足。

不满足条件时计划为空，活动状态不保存裂口、损伤或逐原木映射，碰撞路径只经过一个布尔短路。

## 结构规划

计划按树 ID 生成确定性种子，并只在创建时执行：

- `2x2` 底面以外的原木按 26 邻域连通组件识别为分支。分支过多时确定性合并为最多四个
  破碎批次，避免每根分支各触发一次 collider 重建。
- 主干在保护核心以上、从靠近树冠处向下生成最多四个裂口带。每个裂口带随机选择 X 或 Z
  方向并分为互补的两侧；两侧都包含同一个完整横截面高度，并各自带一层有界错落纹理。
- 真实 fragment 渲染锚点对应的原木，以及它附近两层低位 `2x2` 主干构成保护核心，永不进入
  破碎组。
- 巨型云杉复用相同的有界错落横断面，但组类型为 `crosscut`。最底部六层完整 `2x2` 主干和
  砍伐后残留的更低方块均属于保护核心；不生成分支组或纵向削薄组。

丛林树运行时随机选择受以下约束：分支必须先于主干；同时最多打开两个未完成裂口；已打开裂口
有更高概率继续扩展。云杉没有已打开裂口时选择最靠近本 tick 最强碰撞点的横断带；一旦一侧已经
开裂，下一次有效冲击必须先完成同一断裂带。随机种子和破碎代际相同就必须得到相同侧面选择，
不能因重载改变结果。

## 冲击与断裂

Cannon 现有碰撞回调提供法向相对速度和接触点。只有速度至少 `1.75` 的接触参与结构损伤；同一
生命周期 tick 的多个接触只保留损伤最大的一个，避免碰撞盒越多就重复记账。损伤使用当前质量、
速度平方以及接触点到锚点的归一化力臂计算，独立碰撞之间可以累计，静止接触和求解器微抖动不累计。

每次有效碰撞最多提交一个侵蚀批次：

1. 仍有分支时，从分支批次中确定性随机选择一个。
2. 分支清空后，在已有裂口和下一个未打开裂口之间受约束随机选择主干一侧。
3. 删除候选原木后，从受保护锚点对全部剩余原木执行一次 26 邻域传播。
4. 所有无法到达锚点的原木与候选原木一起破碎；随之失去原木支撑的树叶和附件并入同一批次。
5. 消耗该批次的结构强度，保留剩余损伤供下一次真实碰撞使用。

因此第一次裂口通常只在主干侧面形成缺损；后续翻滚或反弹可能打开下一处裂口，也可能补完已有
裂口。一旦完整横截面失去最后连接，上方树冠立即因真实失联转为掉落物，而基座核心始终保留。
云杉总是先补完已经打开的同一横断带，因此最多经过两次真实有效冲击就会完成一处折断，避免把
规则主干长期保留为碰撞盒更多的残缺形状。

## 数据安全

结构损伤随现有周期状态快照保存，不为每次碰撞增加持久化写入。真正破碎前必须：

1. 增加 `logBreakGeneration`，把最终删除键集和破碎成功后的目标 sleep 阈值写入 `pendingLogBreak`。
2. 结构和状态记录均确认耐久后，才批量修改装配体并生成带代际 tag 的掉落。
3. 删除成功后过滤快照、树叶表和剩余裂口计划，清除 pending 并提交。

恢复发现 pending 时先检查确定性掉落 tag、补齐副作用并提交过滤结构，之后才恢复唯一装配体。
事务重试不允许新碰撞扩展已落盘键集。随机选择发生在 pending 保存之前，而 pending 保存的是精确
删除键集，所以崩溃恢复不需要重新随机。

每根原木的 sleep 成本在砍伐时按工具只计算一次。事务目标阈值由旧阈值减去“待删原木数乘以
单根成本”得到；叶片和附件不参与扣减。运行时成功删除与强退恢复都直接提交 pending 中的同一个
目标值，因此不会扫描剩余结构，也不会因恢复路径不同产生计时偏差。已经累计的 sleep tick 保留。

## 性能边界

- 普通直立树和普通云杉没有新增逐 tick 工作、世界读取、实体查询或拓扑检查。
- 巨型丛林树、巨型云杉与华丽橡树只在已有碰撞回调内进行常数次数值运算；同一 tick 只保留一个
  最大值及其局部接触点。
- 连通传播、叶片支撑传播、LootTable、粒子和 collider 重建只在实际破碎时运行，并合并为一个
  删除批次。
- 分支批次和主干裂口均有固定上限，不能把一次巨树倒伏退化为数十次完整网格重建。
- 方块破坏粒子最多采样 32 个；掉落继续使用批量堆叠与确定性位置采样。
- 低性能档的预裁剪只在装配创建时执行一次；分支不会进入动态 Shape、fragment、浮力点或后续
  生命周期探针，掉落则复用现有耐久记录、游标和实体标签去重。
