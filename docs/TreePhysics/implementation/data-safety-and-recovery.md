# 装配体数据安全与野实体恢复协议

本轮目标按以下顺序执行：

1. 不留下持久化野实体，不让失效视觉实体阻塞或伪装成有效物理装配体。
2. 能证明保存状态和源方块安全一致时，恢复完整物理装配体。
3. 无法证明可以恢复时，使用已持久化状态直接结算掉落物；如果连掉落位置或世界读写都不可证明安全，则暂缓处理并保留记录，等待可读条件，而不是冒险生成重复内容。

## 事务边界

树木转换为装配体采用 `preparing/sourceCommitted` 两阶段记录：

- 先分配持久化 ID 和视觉代际，创建带所有权 tag 的视觉实体。
- 完整保存方块快照、物理状态、叶片质量档、染色、掉落工具和视觉 ID。
- 记录确认落盘后才移除世界方块。
- 世界方块移除成功后再提交 `sourceCommitted=true`。

因此，强制结束可以发生在任意阶段。重载时对每个源位置做逐块分类：仍完全一致则撤销准备记录；发现已移除方块则继续完成移除并恢复；出现外部冲突则只保留可证明属于本次事务的方块并直接结算。结构过滤和终止状态先落盘，待结算记录不会重新创建物理或视觉装配体。

高成本藤蔓、垂根、苍白垂苔和悬挂胎生苗可能在建树时不进入装配体。它们仍属于同一个准备事务：
裁剪快照先进入结构记录，`sourceCommitted=true` 持久化后才启动掉落 job。每批完成后写入独立游标，
掉落实体使用稳定 tag 去重；完成时先保证末尾游标持久化，再清空结构列表。跨域直接结算会接管剩余
附件，熔岩终止则等待附件结构日志清空，因此不存在第二个无日志掉落生产者。

活动装配体的巨型丛林树侵蚀、巨型云杉横向折断和华丽橡树分支破碎使用独立代际事务。当前分支或随机裂口、与受保护锚点失联的远端原木以及同步失去支撑的树叶和
附件键集先写入 `pendingLogBreak`，确认结构和状态记录均持久后才修改物理装配体。掉落物使用
`log_break_<tree id>_<generation>` 派生的确定性 tag；恢复时先检查现有 tag、补齐掉落，再过滤保存
结构并恢复唯一装配体。`pendingLogBreak` 同时保存按实际待删原木数计算的目标 sleep 阈值，正常提交和
恢复提交使用同一个值。随机算法只在事务开始前运行，pending 保存最终键集。一次已落盘事务重试时，新到达的叶片或附件事件保留在原队列中，
必须等旧键集完成后再开新事务，避免强退窗口内出现未记账删除。

## 视觉实体所有权

树 fragment 和通用逐块 `tree_physics:physics_block` 在生成后立即写入 `tree_physics_tree_<id>_<generation>` tag，必须先完成 tag 才设置可见属性。tag 写入失败会立即移除实体并让创建失败。

- 启动后每个玩家所在维度最多执行一次有界 family/type 扫描（树 fragment 与回退 `physics_block` 各一个受限查询），清理未被当前生命周期管理的树视觉实体。
- 后续玩家进入新维度时只扫描该新维度；查询失败按 20 tick 退避重试。
- `entityLoad` 对延迟加载的未知树视觉实体执行一次延迟清理。
- 通用 `tree_physics:physics_block` 没有 fallen-tree tag 时永远不被该协议删除。
- 恢复前按保存包围范围再次清理旧视觉代际；成功恢复的实体获得递增代际 tag。

清理和恢复不加入 Cannon 子步、拖拽子步、碰撞伤害查询或常驻粒子路径，只在启动/跨域恢复和实体加载边界运行。

## 跨维度和不可读区域

活动装配体在原维度仍有玩家时继续运行。原维度没有玩家时沿用现有安全结算路径；边界威胁连续确认后冻结到最后可读姿态并结算。保存树只在原维度有附近玩家且包围范围可读时恢复。

保存记录标记为待结算时，恢复过程直接使用 Cannon 的 YZX 四元数变换把保存的局部方块位置转换为世界掉落位置，不创建临时物理装配体或额外视觉实体。最终结算在一个同步批次内完成：最多 64 个剩余方块保持各自位置，超过时在最终包围盒下表面中心集中并合并兼容物品堆。批次 tag 用于识别极窄中断窗口内已经生成的掉落，`pendingSettlement` 保证恢复过程不会重建装配体。

## 性能约束

常驻活动树的物理、渲染实体数量、同步属性、粒子、音效、伤害查询和每 tick 世界探测没有新增工作。新增成本仅为：

- 已有树持久化切片中的少量 ID/tag/代际字段；
- 启动或新维度首次可见时的一次有界实体扫描；
- 恢复前一次按树包围范围的实体扫描；
- 最终结算只有一次同步掉落批次、一次开始事务和一次终止提交，不再逐操作运行 job 或重写游标；
- 巨型丛林树/云杉资格、华丽橡树分支、分支批次和主干裂口只在装配体创建时生成；其他普通树和
  普通云杉计划为空。活动期间
  复用已有碰撞回调且每 tick 只保留最大冲击，断裂发生时与树叶和附件合并为一次删除、一次
  collider 重建和一次结构持久化；结算时间只执行一次整数扣减，不新增常驻扫描、刚体或显示实体；
- 命中高成本附件阈值时最长 20 tick 的一次性附件掉落 job；活动树不新增常驻探测。

## 验证

当前回归覆盖未知/托管/通用视觉实体、视觉代际、直接结算、准备事务完整/移除/冲突/不可读、跨维度保留与结算。`npm run check`、完整 Vitest、debug/release 构建均需通过；Bedrock 实机仍需验证强杀后台、跨维度传送、玩家重新进入原维度以及多个大型树同时恢复。

本协议是 fail-closed：在 SAPI 世界读取或持久化 API 本身不可用时不能宣称数学意义上的百分之百恢复，但所有可判定分支都优先避免重复实体和失效装配体，无法证明安全的分支不会生成新的物理/视觉实体。
