# 低档位精确世界快照实施计划

## 1. 目标与不可变边界

本计划只修改低档位物理的世界同步实现。目标是恢复旧物理原型的 `8x8x8` 世界快照、
事件驱动失效和限额重建，同时完整保留当前项目已经具备的物理与玩法语义：

- 台阶、楼梯、门、活板门、栅栏门等方块的实际碰撞盒与状态方向；
- 每种世界方块现有的材质、摩擦、弹性和 `collisionResponse`；
- 水与岩浆的精确液面、浮力、阻力、入液事件和岩浆浸没比例；
- 树叶等世界传感方块的接触语义；
- 玩家放置和破坏方块、爆炸、活塞、树木移除、事务回滚、恢复清理和根部土壤恢复；
- 当前伤害、破碎、拖拽、掉落、持久化、渲染和数据安全行为。

高档位是严格回归边界，不共享低档位快照碰撞体，也不进入低档位构建或审计队列：

- 继续实时读取当前世界；
- 继续执行每游戏 tick 三次 `1/60s` 子步；
- 碰撞、液体、玩法和渲染结果不变；
- 从低档位切换到高档位时，移除所有快照静态体并清空全部队列；
- 从高档位切换到低档位时，从空缓存开始，不能沿用高档位扫描的临时数据。

本计划不降低物理步频，不简化动态树木形状，不删减任何玩法，也不把完整方块碰撞近似应用到
非完整方块。快照只存在于运行时内存；没有测量证据前，不写入动态属性或存档。

## 2. 当前实现与实际问题

当前低档位已经具备 `8x8x8` 缓存雏形，并在样本中保存了精确 `shape`、`materialId`、
`collisionResponse`、液体类型和液面高度。因此本轮不是重新引入一套近似算法，而是把已有
精确样本缓存升级为真正可复用的世界快照。

现有路径仍有四项主要浪费：

1. 每棵活动树每 tick 都从缓存样本中重新筛选当前区域；
2. 每 tick 都重新执行完整方块贪心合并和非完整方块布局构建；
3. 每个合并盒分别创建一个 Cannon 静态 Body，世界 Body 数偏高；
4. 失效主要是逐点删除，爆炸、活塞和整棵树移除会重复处理同一 `8x8x8` 块。

改造后的低档位热路径只需要计算装配体本 tick 覆盖了哪些快照键、激活已有静态体、查询已缓存
液面，并对缺失或脏块使用精确临时兜底。稳定世界不再反复读取、解析和网格化相同方块。

## 3. 快照数据模型

快照键固定为：

```text
dimensionId | floor(x / 8) * 8, floor(y / 8) * 8, floor(z / 8) * 8
```

每个快照保存：

- 对齐后的 `8x8x8` 边界；
- 精确碰撞盒；
- 每个碰撞盒的材质 ID 与 `collisionResponse`；
- 精确液体类型与液面高度；
- 精确内容签名；
- 构建、最后使用、最后审计 tick；
- `clean`、`dirty`、`queued`、`building` 状态；
- 按 `(materialId, collisionResponse)` 分组的预构建静态碰撞体。

完整方块只允许在同一快照、同一材质和同一 `collisionResponse` 组内贪心合并。非完整方块的
每个碰撞盒保持现有精度，不跨方块或跨状态近似合并。每组创建一个静态 Cannon Body，并把
该组所有 Box 作为多个 Shape 挂在 Body 上；不同材质或响应组绝不混合。

快照 Body 由同一维度内所有装配体共享。运行时按当前覆盖块维护激活引用：首个装配体使用时
加入 Cannon World，最后一个装配体离开时从 World 移除，但可保留预构建对象供再次使用。
未使用快照超过 `400` tick 后彻底回收，避免走过的区域长期增加 broadphase 负担。

液体不转换为静态 Shape。低档位继续以当前浮力采样点查询快照中的精确液体类型与液面，并
完全复用现有浮力、阻力、入水/入岩浆事件和 `lavaSubmersionRatio` 算法。
浮力点可能位于固体碰撞盒范围之外，因此每个活动刚体还要单独记录其上、下液体采样格涉及
的快照键；这些仅液体使用的快照同样参与失效、低频审计和引用保护，但不会激活静态 Body。

## 4. 构建队列与绝对正确性兜底

采用旧原型的分级预算，但构建内容改为当前精确数据：

- 每 tick 最多构建 `4` 个活动高优先级快照；
- 每 tick 最多构建 `2` 个普通预热或审计快照；
- 相同快照键在所有来源和队列中只保留一次；
- 活动装配体当前需要的缺失或脏快照总是进入高优先级队列；
- 不再活动的脏快照只标记失效，等再次接近时才重建。

预算只能削平构建尖峰，不能改变物理结果。只要活动装配体覆盖的快照尚未就绪，该 `8x8x8`
范围就临时调用当前的精确实时扫描、形状解析、材质解析、传感判定和液体算法。临时扫描必须
只覆盖缺失或脏快照与装配体扫描区域的交集，避免和已激活快照形成重复碰撞体。

因此任何时候都禁止：

- 使用已标脏的旧碰撞或旧液面；
- 把未完成快照当成空气；
- 因构建预算耗尽而让装配体穿过世界；
- 为避免临时扫描而回退到整方块近似。

快照构建完成后，在物理 step 边界原子替换临时路径。失效时先撤下旧 Body，再由临时精确
扫描接管，直到新快照就绪。

## 5. 批量失效 API

在现有单点接口之外增加批量接口：

```ts
PhysicsWorld.invalidateWorldMeshBatch(
  dimension: Dimension | string,
  locations: readonly Vector3[]
): void
```

批量接口只做坐标归一化、快照键去重、标脏和队列优先级调整，不在事件回调中读取世界。
现有 `invalidateWorldMesh(..., radius)` 保留，并复用同一内部失效实现。

楼梯、栅栏、墙、玻璃板和紫颂植株等精确碰撞盒会依赖相邻方块。每个变化位置除失效自身
快照外，还必须把六个正交相邻格涉及的快照键一并去重失效；相邻格仍在同一 `8x8x8`
快照时不会增加任务，只有变化发生在快照边界时才会增加邻接快照。这个过程只计算整数键，
不读取世界，也不会把邻接方块近似为完整方块。

失效一个快照时执行以下操作：

1. 标记为 `dirty`，取消尚未完成的同键构建结果；
2. 立即从 Cannon World 撤下旧静态 Body；
3. 清除旧液体数据，禁止继续读取；
4. 若本 tick 有活动装配体需要它，加入高优先级队列；
5. 唤醒受变更位置影响的睡眠装配体仍沿用现有逻辑，不把缓存失效等同于全维度唤醒。

## 6. 方块变化事件覆盖

### 6.1 已有必须覆盖的来源

| 来源 | 失效范围与时序 |
| --- | --- |
| 玩家放置方块 | 放置位置所在快照；沿用现有附近装配体唤醒 |
| 玩家破坏方块 | 破坏位置所在快照；沿用现有附近装配体唤醒 |
| 爆炸 | 在单次 `world.afterEvents.explosion` 中批量提交全部 `getImpactedBlocks()` 位置 |
| `blockExplode` | 只保留人工树登记清理，不再重复逐方块失效 |
| 活塞 | 活塞基座、正前方、全部附着方块及每个附着方块沿运动方向前后各一格 |
| 树木移出世界 | 成功提交后一次性批量失效全部实际移除位置 |
| 移除事务回滚 | 恢复完成后一次性批量失效全部实际恢复位置 |
| 恢复期来源清理 | `FallenTreeLifecycle.#resolvePreparedSource` 实际清除的位置批量失效 |
| 根部土壤恢复 | `setType` 成功后失效根部位置 |
| 脆弱世界方块破坏 | 项目执行 `setblock ... air destroy` 成功后失效该位置 |

活塞事件存在中间状态，必须把同一批键在当前 tick 标脏，并在下一 tick 再标脏一次。附着方块
位置无论 API 返回移动前还是移动后坐标，沿方向的 `-1/0/+1` 覆盖都能包含源格和目标格；
基座与正前方则覆盖活塞头和伸缩状态。两次提交都按快照键去重。

爆炸处理复用当前物理爆炸监听已经读取的 `getImpactedBlocks()`，不能再由 `blockExplode`
逐点重复失效。人工树登记仍可继续使用 `blockExplode` 的旧排列信息。

树木世界移除模块通过注入的批量变更回调报告实际修改成功的位置。失败回滚必须在恢复结束后
报告恢复位置，不能只覆盖成功路径。生命周期恢复清理和脆弱方块命令也使用同一回调，避免
项目自有世界写入绕过缓存。

### 6.2 `@minecraft/server 2.8.0` 可补充的近零常态开销事件

| 事件 | 使用方式 |
| --- | --- |
| `playerInteractWithBlock` | 只处理首次交互；门、活板门和栅栏门失效被点击格，门额外失效同列 `y-1/y+1` |
| `playerInteractWithBlock` + 桶 | 检测交互前后物品是否为水桶、岩浆桶或空桶，失效被点击格及点击面相邻格 |
| `pressurePlatePush` | 失效事件方块位置 |
| `pressurePlatePop` | 失效事件方块位置 |

这些监听只在低档位执行筛选和失效；高档位不得进入缓存路径。交互事件必须先按方块类型或桶
类型过滤，普通开箱、工作台和持续按住交互不能制造失效风暴。

下列事件不用于缓存失效：`buttonPush`、`leverAction`、`tripWireTrip`、`targetBlockHit`、
`projectileHitBlock`。它们要么不改变自身有效碰撞形状，要么无法指出被红石信号改变的下游
门、活板门或其他方块。盲目扫描红石邻域会增加常态成本，仍不能保证完整覆盖。

## 7. 无事件变化的低频安全审计

2.8.0 没有通用方块变化事件，也没有区块 revision。命令、自然更新、红石下游变化、流体
扩散或消退、重力方块和部分实体触发状态无法被上述事件百分之百定位。为了不把这些情况永久
留在旧快照中，增加严格限额的安全审计：

- 只审计当前仍被装配体使用的快照；
- 快照连续稳定 `600` tick 后才具备审计资格；
- 整个 `PhysicsWorld` 全局最多每 `20` tick 审计一个快照，而不是每维度各审计一个；
- 候选按最久未审计优先，避免单个快照永久饥饿；
- 审计重新计算精确形状、材质、传感响应、液体类型与液面签名；
- 签名未变化时只更新审计时间，不重建 Body；
- 签名变化时立即撤下旧 Body，并把本次已经读取的精确结果直接提交为新快照；若不能原子
  提交，则进入高优先级队列并由实时精确扫描兜底，禁止再读一次旧数据。

该审计平均最多增加一次 `8x8x8` 批量查询/秒，是对 2.8.0 事件缺口的安全保险，不恢复
旧实现每 `100` tick 批量刷新多个快照的成本。自然或命令变化仍可能在审计前短暂不可见，
这是当前 SAPI 无通用变更事件下低档位无法彻底消除的延迟；高档位继续提供实时世界真值。

## 8. 配置变化与档位切换

下列情况必须统一调用“清空低档位世界状态”，同时撤下 Body、清缓存、清高低优先级队列和
审计游标：

- `worldMeshCache` 从启用切到关闭；
- 世界方块属性表发生变化；
- 世界传感方块 predicate 发生变化；
- 任何会改变碰撞形状解析或材质映射的配置发生变化。

切换到低档位时新建空状态，首批未完成快照走实时精确兜底；切换到高档位时彻底销毁低档位
静态 Body。材质接触参数只需继续重建 Cannon ContactMaterial；若快照组引用的材质 ID 没有
变化，不应重扫世界。

## 9. 实施顺序

### 阶段 A：内核数据结构与共享 Body

1. 将 `CachedWorldBlockSample[]` 升级为快照几何组、液体表和签名；
2. 在构建期完成精确形状解析和按材质/响应分组；
3. 每组改为单静态 Body 多 Shape；
4. 增加活动引用、回收和统一清理；
5. 保留现有实时扫描作为缺失/脏块兜底。

### 阶段 B：队列与生命周期

1. 增加 `4` 个高优先级和 `2` 个普通任务的 tick 预算；
2. 加入键去重、取消过期结果和原子提交；
3. 实现低档位切入、切出和属性变化时的完整清理；
4. 增加 `600/20` 低频安全审计。

### 阶段 C：批量失效与事件桥接

1. 增加批量 API，并迁移已有 place/break/root 路径；
2. 合并爆炸逐点失效；
3. 接入活塞源格、目标格和次 tick 二次失效；
4. 为树木提交、回滚、恢复清理和脆弱方块破坏注入批量回调；
5. 接入手动开合方块、桶和压力板事件。

### 阶段 D：回归测试与实机验收

完成单元、集成、构建检查后，再进行同一世界、同一树形、同一档位的真机 A/B 测试。没有
证据时不进一步调整 `8`、`4+2`、`600/20` 或 `400` 这些参数。

## 10. 必须新增的自动化验证

### 10.1 精确性

- 低档位缓存前后，完整方块、台阶、楼梯、门、活板门、栅栏门和压力板接触结果一致；
- 材质摩擦、弹性和传感方块 `collisionResponse` 一致；
- 低档位与高档位的浮力方向、速度、入水/入岩浆事件参数和岩浆浸没比例一致；
- 缓存构建预算耗尽时仍使用精确临时碰撞，装配体不能穿地或漏掉液体；
- 跨 `8` 格正负坐标边界的键计算与失效范围正确。

### 10.2 复用与性能结构

- 两棵树覆盖同一快照时共享同组静态 Body，不按树复制；
- 稳定快照在审计到期前没有重复实体方块读取、形状解析或贪心网格化；
- 批量失效把数百个位置去重为实际涉及的快照键数；
- 未使用快照按 `400` tick 回收，且 Cannon World 不残留静态 Body；
- 安全审计严格满足全局每 `20` tick 最多一个，并能发现未广播变化。

### 10.3 事件完整性

- 玩家放置、破坏和桶操作；
- 爆炸批量位置且 `blockExplode` 不重复失效；
- 活塞源格、目标格、附着方块和次 tick 状态；
- 树木移除成功、部分失败回滚和恢复期来源清理；
- 根部土壤恢复与脆弱方块命令破坏；
- 门、活板门、栅栏门和压力板状态变化。

### 10.4 高档位零回归

- 仍为每 tick 三次 `1/60s`；
- 每个活动 tick 继续实时扫描，不命中快照；
- 不创建快照静态 Body，不累积构建或审计任务；
- 高低档位往返切换后无静态 Body、液体表或队列残留；
- 现有碰撞、液体、伤害、破碎、拖拽、TNT、活塞、恢复和渲染测试结果不变。

## 11. 完成标准

代码完成后必须通过：

```powershell
npm run check
npm test
git diff --check
```

同时检查 release 构建产物 `packs/TreePhysics/BP/scripts/*.js`：不得混入 profiler、TPS 输出、
诊断命令或调试绘制。真机验收至少包含多个普通树、巨型云杉、巨型丛林木、复杂台阶/门碰撞、
水与岩浆、爆炸、活塞和档位热切换。

本计划的成功标准不是“低档位永远不读取世界”，而是：稳定世界只为首次构建和极低频审计
付费；已知变化由事件精确标脏；任何缓存空窗都由当前精确算法接管；高档位完全不受影响。
