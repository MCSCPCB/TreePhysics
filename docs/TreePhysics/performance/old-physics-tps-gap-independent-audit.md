# 旧物理原型与当前项目的 TPS 差距独立审计

## 1. 审计范围

本次审计只比较以下两套实际源码，不采用项目内已有性能文档的结论：

- 当前项目：`src/`
- 旧物理原型：`sample/old-physics/test_packs/BP/scripts/main.js`

只讨论服务端/脚本线程 TPS。客户端 FPS 已由测试确认没有版本间退化，因此渲染实体仅分析其实体管理、SAPI 写入和服务端同步成本，不分析 GPU 绘制成本。

审计覆盖物理解算、世界碰撞同步、基岩版 SAPI、复合形状、树木生命周期、视觉实体、持久化、掉落物、粒子、音效、玩家交互、TNT 和活塞。文中微基准使用同一测试桩比较相对差异；测试桩中的 `getBlock`、`getBlocks`、`getEntities`、`teleport` 和 `setProperty` 远比真机 SAPI 便宜，因此微基准不能替代真机毫秒数，只能证明算法缩放关系。

## 2. 结论

当前版本的 Cannon-es 核心没有发生足以解释差距的性能退化。两版均使用 Cannon-es、SAP broadphase、8 次求解迭代和刚体睡眠。真正原因是两版所谓的“一个物理体”不是等量工作：

1. 旧版一个物理体通常是一个 Box、一个视觉实体、每游戏 tick 一次 `1/20s` 步进。
2. 当前一棵树虽然在统计上仍是一个动态 Body，却可能含几十个动态碰撞 Shape、多个视觉片段实体，并在高档位每游戏 tick 固定执行三次 `1/60s` 子步。
3. 当前活动树还要执行实时世界碰撞扫描、叶片与附着物探针、脆弱世界方块探针、伤害查询、浮力采样、破碎状态机、持久化和跨维度安全检查。旧原型没有这套树木玩法层。
4. 旧版使用 8x8x8 世界快照、事件驱动标脏、限额重建、整方块近似和整维度停步。当前高档位为了实时准确性放弃了这些近似。

因此，“旧版 40 个物理体仍可玩，当前十几个物理体严重掉 TPS”并不证明当前 Cannon-es 每 Body 变慢了。它主要证明当前每棵树的 Shape 数、每 tick 子步数、SAPI 调用数和玩法工作量远高于旧版单 Box 测试体。

四个候选原因的判定如下：

| 候选原因 | 判定 | 说明 |
| --- | --- | --- |
| 物理引擎本身变差 | 不是主因 | 引擎、broadphase 和 solver 配置没有本质退化；等量简单形状仍可保持较低成本 |
| 多形状装配体天生成本更高 | 是主要原因之一 | Cannon 按 Shape 参与 AABB、候选对和窄相检测，Body 数不能代表真实物理规模 |
| 额外玩法牺牲性能 | 是主要原因之一 | 世界探针、伤害、浮力、破碎、持久化和安全恢复全部是旧原型没有的工作 |
| 旧优化方案被砍掉 | 是主要原因之一 | 高档位放弃 20 Hz、长期世界快照、整方块近似、单视觉实体、粗写回阈值和无活动维度停步 |

不存在既完整保留当前物理准确性、玩法、视觉与数据安全，又把任意复杂树等价成旧版单 Box 物体成本的方案。若目标是“完全回到旧版性能”，必须主动恢复旧版的近似并删除一部分当前功能。

针对“多棵树正在运动”的稳态 TPS，按真机预期贡献从大到小可概括为：

1. 实时世界 SAPI 扫描、真实形状解析与静态碰撞体重建；
2. 动态 Shape 数乘以三个物理子步形成的 Cannon 成本；
3. 叶片、附件、世界脆弱方块和伤害等生命周期探针；
4. 多视觉片段的实体管理与 transform/property 写入；
5. 周期持久化和跨维度安全状态机；
6. 掉落物、粒子和音效等事件尖峰。

该排序不是固定百分比：纯空中运动会降低第 1 项，复杂落地接触会提高第 2 项，巨型丛林木会提高第 3、4 项，最终结算的单个 tick 则会让第 6 项暂时成为主导。

## 3. “物理体数量相同”为何不等量

| 每个统计对象承担的工作 | 旧版测试体 | 当前树木装配体（高档位） |
| --- | --- | --- |
| Cannon Body | 1 | 1 |
| 动态 Shape | 通常 1 个 Box | 1 至几十个 Box，取决于树形和表示策略 |
| 每游戏 tick 子步 | 通常 1 次 `1/20s` | 固定 3 次 `1/60s` |
| 世界碰撞 | 8x8x8 快照缓存，限额重建 | 活动区域实时扫描、真实方块形状与材质、液体和传感器 |
| 视觉实体 | 通常 1 | 多个原木、叶片和附着物片段 |
| 活动时视觉写入 | 单实体，低速可延迟 3 tick | 每片段可 teleport，并写 pitch/yaw/roll；阈值更严格 |
| 树叶/附着物 | 无树木语义 | 独立联通性、接触与破碎探针 |
| 世界破坏 | 无 | 脆弱方块检测和排队破坏 |
| 生物伤害 | 无 | 空间实体查询、日志接触点速度和伤害判定 |
| 液体 | 无精确浮力 | 水/岩浆采样点、入液事件和持续受力 |
| 数据安全 | 无树木恢复事务 | 周期快照、动态属性、跨维度恢复、去重和野实体清理 |

“一个 Body”只是容器数量。对 Cannon 来说，更接近真实负载的指标是：动态 Shape 数、静态世界 Shape 数、潜在碰撞对、接触方程数、solver 子步数；对基岩版脚本来说，还要加上 SAPI 调用次数和视觉实体写入次数。

## 4. 定量证据

### 4.1 Shape 数是独立的大倍率变量

同一测试桩中的装配体基准：

| 场景 | 结果 |
| --- | ---: |
| 980 方块，自动表示，2 shapes，15 visuals，1 棵 | 0.2242 ms/tick |
| 980 方块，完整表示，57 shapes，15 visuals，1 棵 | 1.5315 ms/tick |
| 980 方块，自动表示，2 shapes，15 visuals，5 棵 | 1.7031 ms/tick |
| 980 方块，完整表示，57 shapes，15 visuals，5 棵 | 9.4036 ms/tick |

仅改变碰撞表示，完整表示已比自动表示慢约 5.5 至 6.8 倍。这直接否定“Body 数相同就应有相同性能”的前提。

另一组生产表示基准中，408 方块、76 shapes 为 0.4049 ms/tick；同树压缩到 13 shapes 后为 0.0676 ms/tick。趋势一致。

### 4.2 60 Hz 相对 20 Hz 是明确倍率

40 个简单动态体、合计 55 shapes 的同机基准：

| 步进模式 | 结果 |
| --- | ---: |
| 高档位，3 x `1/60s` | 3.1525 ms/tick |
| 低档位，1 x `1/20s` | 1.1746 ms/tick |

在不包含真机 SAPI 延迟的情况下，20 Hz 已快约 2.68 倍。该差距来自确定的子步数量，不是测量噪声。

### 4.3 睡眠能大幅降低成本，但当前仍不是绝对零成本

10 棵 980 方块睡眠树在测试桩中约 0.0998 ms/tick，说明 Cannon 和视觉写回在睡眠后已经得到有效抑制。不过真机仍存在测试桩没有计入的周期工作：当前内核每 10 tick 检查睡眠体支撑，每 20 tick 检查完整环境；生命周期和跨维度安全状态机也继续运行。

旧原型通过 `shouldStepDimension()` 判断维度是否存在活动体、近期活动或拖拽；没有活动时连 `physicsWorld.step()` 都不调用。当前项目仍按 tick 进入各维度 runtime，再由睡眠状态减少内部工作。因此多个静止巨木的 TPS 压力应明显小于运动时，但不会严格等于零。

## 5. 各阶段完整成本分析

### 5.1 创建阶段

当前创建一棵树需要捕获方块和状态、建立树结构、生成碰撞表示、计算质量/质心/惯量/浮力点、打包视觉片段、生成多个实体、写入 Molang 属性、建立持久化记录并安全移除世界方块。巨树创建时这些成本大体随方块数、片段数和结构复杂度增长。

`runJob` 可以把可分割的捕获、附件结算或持久化工作摊到多个 tick，降低单 tick 卡死风险，但不会降低总 CPU/SAPI 工作量，也无法处理 Cannon 单次 step 内不可分割的成本。因此它适合创建和结算尖峰，不是十几个活动刚体持续掉 TPS 的根治方案。

旧原型的单 Box 测试体没有树结构捕获和上述事务，创建成本不具可比性。

### 5.2 活动物理解算

当前高档位的主要纯物理成本由三项相乘：

- 每树动态 Shape 数；
- 动态 Shape 与世界静态 Shape 形成的候选对/接触数；
- 每游戏 tick 三次 solver 子步。

复合装配体不是“多刚体”，而是“一个 Body 上的多 Shape”。这能避免多个动态 Body 之间的约束和自碰撞，但不会让 Shape 免费。分支、空洞、不规则树干和细长结构会提高 AABB 重叠、窄相检测与接触方程数量。把一棵树拆成多个小 Body 通常还会增加 broadphase 对、刚体积分和实体同步，因此不能保证获益；只有把断裂部分直接结算为掉落物，才真正减少活动 Shape 和装配体工作量。

### 5.3 世界碰撞与 SAPI

这是当前真机最可能超过纯 Cannon 的热点。活动体每 tick 需要根据当前位置、速度、角速度和 Shape 阴影构造预测扫描区域，然后通过基岩版维度 API 读取世界方块，解析真实碰撞形状、材料、液体表面和脆弱方块传感器，再重建静态 Cannon 碰撞体。

单次 `getBlock` 在小基准中可能不显著；问题是它处于“活动树 x 扫描体积 x 每 tick”的乘积内。旧原型的 8x8x8 快照长期复用，只在玩家放置/破坏事件时标脏，并限制每 tick 最多重建 4 个高优先级块和 2 个普通块。它还把空气、液体、固体简化成少数类别，并把完整固体按整方块处理。

静态 Cannon 组织方式也不同：旧原型把一个快照块的多个 Box Shape 放在同一个静态 Body 上；当前实时网格为每个 greedy box 建立独立静态 Body。后者便于按世界扫描结果增删和复用盒子，但会提高 broadphase 中的 Body 数及布局维护成本。

旧缓存取得高性能的代价是缓存可能过期：命令、爆炸、活塞和自然方块变化不一定及时触发失效；台阶、栅栏等非完整方块的碰撞不准确；液体、逐方块摩擦/弹性和脆弱方块传感无法保持当前质量。

### 5.4 树木生命周期与额外 SAPI

活动树除正式 Cannon collider 外，还运行独立玩法探针。按当前上限，一棵活动巨树单 tick 最多可涉及数十个附件/脆弱节点探针、数十个世界非叶探针及叶片档位探针；运动采样还可能同时检查当前与预测位置。伤害阶段会合并空间范围后调用 `dimension.getEntities()`，再对候选实体做日志接触和相对速度判断。

这些机制分别实现：叶片和附着物碰撞破碎、压碎世界脆弱方块、巨树侵蚀断裂、倒伏伤害。它们不是 Cannon 引擎退化，而是当前玩法明确购买的额外成本。巨型丛林木比规整云杉更重，正是因为它拥有更多分支、藤蔓和附件状态，既增加 Shape/视觉复杂度，也增加生命周期探针。

TNT、活塞和拖拽主要是事件驱动成本：没有爆炸、活塞动作或玩家拖拽时，它们不会解释稳定阶段十几个树持续掉 TPS。删除它们对常态 TPS 收益很小。

### 5.5 视觉实体与服务端同步

当前片段渲染已远优于一方块一实体，但一棵大树仍可能拥有多个原木、叶片和附件实体。活动时，每个有效片段可进行一次 `teleport` 和 pitch/yaw/roll 属性写入。当前位置阈值为 `1/1024`，旋转阈值为 `0.05` 度；旧原型为位置 `0.0025`、旋转 `0.35` 度，并在低速时最多每 3 tick 写回一次，还允许 `0.02` 格和 `1.5` 度的延迟误差。

这些调用会占用脚本和实体同步 TPS，即使本审计不讨论客户端 FPS。睡眠后当前渲染器会在完成一次最终同步后停止重复写回，因此静止实体的主要剩余成本是基岩版本身的实体管理、周期世界验证和生命周期，而不是每 tick teleport。

### 5.6 持久化与数据安全

当前树按切片刷新运动状态，并用签名避免内容未变时重复写入；结构与状态拆分保存，破碎和最终掉落使用持久事务、标签去重及恢复状态机。跨维度逻辑还会查询玩家、恢复保存体、清理重复视觉和处理超出安全范围的装配体。

这部分对每 tick 的稳定成本通常小于活动世界扫描和 Cannon，但会形成周期尖峰，并使睡眠体不能像旧原型那样完全被遗忘。删除它可以减少少量常态成本和恢复尖峰，但会重新引入崩溃退出后重复装配体、野实体、丢失方块或重复掉落，因此不是安全优化。

### 5.7 掉落物

最终结算会先生成原版 loot，再调用 `dimension.spawnItem()`。当前已有两层控制：总物品数超过 16 时可以按可堆叠物合并；最终操作数量过大时将掉落集中到树木底部附近，并对粒子采样。掉落物生成仍可能在移动端造成明显单 tick TPS 尖峰，因为 loot 生成、实体创建、标签和原版物品实体初始化都在该阶段发生。

掉落物不是活动树持续掉 TPS 的主因：树还在运动且未结算时不会持续生成最终掉落物；结算完成后它们由原版物品实体系统管理。进一步合并或减少掉落只能改善破碎/销毁瞬间，不能恢复“40 个活动体”的稳态性能。

### 5.8 粒子

碰撞、叶片破碎、最终结算、水花和岩浆飞溅通过 `spawnParticle()` 触发。当前大批结算已有确定性采样上限，且粒子主要在事件发生时生成。粒子调用会占用脚本时间并可能造成事件帧尖峰，但没有碰撞或破碎时没有持续生成，因此不能解释稳定活动阶段差距。

完全禁用粒子会让破碎、入水和入岩浆反馈明显退化，却只能改善事件尖峰；它不应排在恢复旧版稳态 TPS 的主要方案中。

### 5.9 音效

碰撞、破碎、入水、入岩浆和烧毁使用 `playSound()`。音效数量远小于世界扫描和 Shape 运算，并且按事件触发。声音高并发可能增加碰撞瞬间的 SAPI 尖峰，但删除声音对十几个持续活动体的平均 TPS 几乎没有决定性作用。

## 6. 旧原型为了性能牺牲了什么

旧版高并发表现不是免费优化，而是一个明显更窄的物理产品：

- 物理时间分辨率只有 20 Hz，而当前高档位是 60 Hz。
- 动态物体通常是一个完整 Box，不表达树枝、空洞和不规则外形。
- 世界静态碰撞依赖长期缓存和完整方块近似，允许世界变化短期甚至长期不一致。
- 不模拟当前水/岩浆浮力和液体进入玩法。
- 不模拟叶片、藤蔓、可可豆、蜂巢等树木附件的局部破碎。
- 不模拟倒伏伤害和脆弱世界方块破坏。
- 一个物体只需要一个视觉实体，不能表现当前逐片段取色、附件和局部消失。
- 不提供当前树木级持久化、跨维度安全恢复、事务去重和野实体清理。
- 无活动体时可以整维度停止物理；它不需要持续验证复杂装配体的世界支撑与安全状态。

所以旧原型的“40 个物理体”更接近 40 个缓存世界中的单 Box，而当前“10 棵树”可能已经是数百个动态 Shape、数十至上百个视觉实体、30 次 Body-step 加大量 SAPI 探针。

## 7. 完全恢复旧版性能的计划与退化排序

以下只列肉眼或 TPS 计数可明显感知的收益，按预期收益从大到小排列。排序针对“多棵活动树导致持续掉 TPS”；水下、结算瞬间和全睡眠场景的局部排序会不同。

### 1. 恢复旧式 8x8x8 世界快照和事件驱动重建

实施：活动体只碰撞缓存网格；每 tick 限额构建；仅已知的放置、破坏、活塞和爆炸事件标脏；超预算区域继续使用旧快照。

预期收益：真机 SAPI 侧最大，尤其是多个大体积树同时运动时。它直接消除大量重复世界读取与网格重建。

必须接受的退化：命令和未订阅的世界变化可使用过期碰撞；台阶、栅栏、门等形状回退为粗近似；逐方块材质、脆弱传感和液体实时准确性降低。若坚持当前所有形状与液体语义，缓存的构建和失效系统会重新变复杂，也不能复现旧版收益上限。

### 2. 高档位从 60 Hz 回退到 20 Hz

实施：每游戏 tick 只执行一次 `1/20s` Cannon step，并重新标定拖拽电机、阻尼和冲量。

预期收益：纯物理基准约 2.68 倍；Shape、接触和 solver 成本均按子步数下降。

必须接受的退化：高速碰撞更容易穿透或抖动，细小接触和快速翻滚稳定性下降，拖拽手感改变，碰撞/水花事件时间分辨率降低。这直接牺牲物理视觉质量。

### 3. 每棵树压缩为一个 Box 或极少量 Box

实施：用包围盒、主干盒或固定少量盒替代当前树形碰撞表示，不再为分支和不规则轮廓保留相应 Shape。

预期收益：现有基准显示 5 至 7 倍量级的表示差异；复杂巨树收益最大。

必须接受的退化：角色和世界会碰到空气区域，分支、空洞、树冠和倾斜外形碰撞失真；倒伏伤害接触点、脆弱方块破坏、浮力和翻滚惯量都必须基于粗形状重做。该项是恢复旧版性能最直接、也是质量损失最大的条件之一。

### 4. 恢复无活动体维度完全停步，并停止睡眠树的周期环境验证

实施：维度没有醒着的动态体、拖拽或近期活动时不调用 Cannon step；睡眠树不再每 10/20 tick 扫描支撑和环境，只由已订阅事件唤醒。

预期收益：多个静止巨木场景可接近旧版零物理成本，对活动树场景收益有限。

必须接受的退化：命令、未覆盖的世界变化或加载边界变化可能不会唤醒树；支撑被间接移除后树可能悬空；数据安全监测响应变慢。

### 5. 恢复一个物理体一个视觉实体和旧式粗写回

实施：一棵树使用单一预制模型实体；位置/旋转采用旧阈值，低速最多每 3 tick 同步一次。

预期收益：明显减少 `teleport`、`setProperty`、实体索引和网络同步，多个活动巨树时最明显。

必须接受的退化：无法继续表现任意捕获树形、逐片段叶色、附件方向和局部破碎；低速运动会出现可见阶梯或延迟。若仍用当前多个片段实体，只恢复粗阈值可取得中等收益，但达不到旧版单实体上限。

### 6. 删除叶片/附件探针、脆弱世界破坏和倒伏伤害

实施：移除生命周期中的世界采样和实体伤害查询，树只参与 Cannon 刚体碰撞。

预期收益：巨型丛林木和多生物场景明显；规整、无附件且远离生物的树收益较小。

必须接受的退化：叶片和藤蔓不再按碰撞破碎，树不能压碎世界脆弱方块，生物不再受到倒伏伤害，当前巨树侵蚀玩法需被删除或改成定时结算。

### 7. 删除液体浮力与逐采样点受力

实施：液体视为空气或普通静态块，不生成浮力点和入液状态。

预期收益：水中/岩浆中多树明显，纯陆地场景很小。

必须接受的退化：树不再漂浮、受水面姿态影响或按岩浆浸泡销毁；入水和岩浆水花只能变为近似触发。

### 8. 删除树木持久化、跨维度恢复和去重清理

实施：装配体只存在于当前脚本会话；卸载、崩溃或跨维度时直接丢弃或立即结算。

预期收益：小到中等的周期与恢复尖峰收益，不会显著改善主要活动阶段。

必须接受的退化：无法保证方块和掉落数据安全；强杀后台后可能丢失、复制或出现野实体。这与当前项目的数据安全第一优先级冲突。

### 9. 进一步集中掉落并关闭大批结算粒子/音效

实施：所有结算物品只在一个锚点按物品种类合并生成；粒子固定为极少量；声音每树只播放一次。

预期收益：移动端最终掉落和大树破碎瞬间明显；活动阶段无明显收益。

必须接受的退化：掉落不再对应原方块位置，破碎、入液和烧毁反馈变弱。当前代码已经进行了大批合并和粒子采样，剩余空间有限。

TNT、活塞和拖拽不列入主恢复路线，因为它们空闲时几乎没有持续成本。删除它们会失去玩法，却不会解决“十几个活动体”问题。

## 8. 三个可达边界

### 完全恢复旧原型级性能

必须至少执行第 1 至 6 项，并对第 7、8 项采用旧原型式简化。最终产品会接近“缓存世界中的 20 Hz 单 Box 物理演示”，不再是当前完整 Tree Physics。即便如此，基岩版版本差异和实体实现差异仍使“完全相同的毫秒数”无法绝对保证，但工作量模型可以回到同一量级。

### 接近旧原型性能

执行第 1 至 4 项，并保留有限片段渲染与部分生命周期。可以获得最大的 TPS 回升，但世界碰撞准确性、60 Hz 稳定性和树形碰撞至少要牺牲一项；否则不能接近旧原型的工作量。

### 保持当前物理质量、玩法、视觉和数据安全

只能继续做缓存复用、批处理、采样上限、脏状态签名和事件合并等常数优化。它们可以减少尖峰或小幅降低平均成本，但不存在还能把复杂巨树压成旧版单 Box 成本的“大块安全优化”。当前低档位已经是用准确性换性能的明确产品档位；高档位若要求与现有行为一致，就不能同时获得旧原型上限。

## 9. 最终建议

若项目的首要约束仍是“不牺牲物理视觉质量、不删除玩法”，不要以旧版 40 个单 Box 为验收标准。应改用等量 Shape、等量子步、等量世界扫描体积和等量视觉实体的基准；在该口径下，当前 Cannon 核心没有证据表明发生严重退化。

若必须让低端设备获得肉眼明显的 TPS 改善，应把第 1 至 4 项作为独立低档位语义，并在界面明确其物理近似。不要把这些近似偷偷应用于高档位，也不要指望仅靠 `runJob`、粒子限流、声音冷却或掉落合并恢复活动阶段性能。
